## 1. BLOCKER (environment, not a main regression) — SpiceDB/AuthZed unavailable, authenticated app unusable

Formbricks v6 hard-requires AuthZed/SpiceDB (`apps/web/lib/env.ts`: *"Formbricks v6 requires
`AUTHZED_ENABLED=true`; configure SpiceDB before starting the server"*). SpiceDB is a
docker-compose service (`docker-compose.dev.yml`: `spicedb`, `spicedb-migrate`,
`authzed-db-bootstrap`). There is no Docker here, and `scripts/setup-local-test-env.sh` does not
provide or substitute for it, so every `can()` call fails.

**Repro**
1. `bash scripts/setup-local-test-env.sh` (completes cleanly, dev server up on :3000)
2. Sign in as any seeded user — `POST /api/auth/sign-in/email` returns 200, session is valid
3. Open `/workspaces/clseedworkspace000000000/surveys`

**Expected:** the survey list.
**Actual:** *"This resource does not exist or you do not have the necessary rights to access it."*
— for **all three** seeded users, including the org **owner** (`admin@formbricks.com`). So this is
the authorization backend failing, not a permission-model outcome.

Server log (`.local-test-logs/dev-server.log`), 339 AuthZed lines:

```
ERROR API V1 Error Details
  error: { "name": "AuthzedError", "message": "authzed_internal",
           "code": "authzed_internal", "operation": "authorization" }
WARN  AuthZed request failed  errorCode: "authzed_unavailable"  grpcStatus: 14
```

Failed operations: `lookup_resources` (workspace discovery), `check_permission`,
`write_relationships`, `reconcile_organization_memberships`, `reconcile_api_key_relationships`,
`projection_outbox_delivery`, `delete_relationships`.

**E2E consequence:** the suite cannot run. 134 tests discovered; the first 4 all failed at the
2.1m timeout, so the run was aborted rather than burning ~2.3h on a known systemic cause.
Root cause confirmed on a single-spec rerun:

```
account-settings-organization.spec.ts:5:5
  Error: page.waitForURL: Test timeout of 90000ms exceeded.
  waiting for navigation to "**/workspaces/**" until "load"
    navigated to "http://localhost:3000/"
```

Login lands on `/`, which needs `lookup_resources` to discover the user's workspaces and redirect.
AuthZed is down, so it never redirects — and essentially every spec starts this way.

**Cannot be fixed from inside this environment:** no Docker; GitHub releases return 403 through
the egress proxy; SpiceDB is not published on npm. `AUTHZED_ENABLED=false` is rejected by the env
schema, so the server will not start without it.

**Also note:** the baseline in the routine prompt (87 tests, ~84 passing, measured 2026-08-12) is
stale — the suite is now **134 tests**.

### What this cost
Every authenticated write path was untestable: server actions, `/api/v1/management` writes,
`/api/v3` writes past the pre-auth stage, the whole app UI, and all permission/tenant-scoping
probes (the `manager@` / `member@` boundary work this routine is meant to do).

**What still worked, and carried the testing below:** public link surveys (`/s/<id>`), response
submission (`POST /api/v2/client/.../responses` → 200), unauthenticated API routes, API-key
*reads*, and v3 request validation that runs ahead of authorization.

### #9425 — `fix(web)`: validate brandColor before it reaches the OG image SVG — **CLEAN**
`/api/v1/client/og`. Every non-canonical hex falls back to the default render (byte-identical to
the no-param baseline); only real hex changes the output.

Rejected → fallback: `#ff0000"/><script>alert(1)</script>`, `url(javascript:alert(1))`,
`#ff0000;}body{display:none`, `red`, 32 hex chars, empty.
Accepted: `#ff0000`, `ff0000`, `#fff`.
`name` probed with `<script>`, `"/><image href=x>`, emoji, CJK, NUL, whitespace → PNG every time,
no injection. 20 KB `name` → 431 at the header limit (pre-existing, not this diff).

### #9403 — `feat(surveys)`: allow mailto: links — **CLEAN** (renderer path; save-time UI blocked)
Save-time validation could not be driven through the editor (AuthZed). Tested the two halves that
were reachable:

*Renderer* — injected hostile anchors into a survey headline directly in Postgres (bypassing
validation, as a tampered write would) and loaded the public survey:

| Stored href | Rendered |
|---|---|
| `javascript:alert(document.domain)` | href **stripped** (`null`) |
| `data:text/html,<script>alert(1)</script>` | href **stripped** |
| `mailto:hello@example.com` | preserved, `target="_blank"` ✅ the feature |
| `https://example.com` + `onclick=` | href kept, `onclick` **stripped** |
| `<img src=x onerror=alert(7)>` | `onerror` **stripped** |

No dialog fired on load or on clicking the `javascript:` anchor. DOMPurify holds; widening to
`mailto:` opened no scheme bypass.

*Validator* — `endingCardButtonLinkRefinement` exercised directly: accepts `mailto:a@b.co`,
multi-recipient, `?subject=`, surrounding whitespace; rejects `mailto:`, `mailto:?subject=x`,
`mailto:a@b`, `mailto:a b@c.co`, `javascript:alert(1)`.

Uppercase `MAILTO:a@b.co` is rejected — but so is `HTTPS://example.com`, which predates this PR,
so the asymmetry is pre-existing, not a regression. Not filed.
