A **Source** defines how external data is mapped into Feedback Records inside a Feedback Dataset.

## Source types

### 1. Formbricks Surveys

Responses of a Formbricks survey are piped into a Feedback Dataset as they arrive. Each question is mapped automatically to a `field_type`, so there is nothing to configure per response.

### 2. API and agent ingestion

Push records into a dataset programmatically from your own systems, or let your agent do it. This is the way to bring in support tickets, app store reviews, NPS tools and anything else that is not a Formbricks survey.

- **Agents:** `create_feedback_record` and `create_feedback_records` over [MCP](/platform/mcp/overview), under the `feedbackRecords:write` scope.
- **Your systems:** the Feedback Records API, documented in the [API v3 reference](/api-v3-reference/introduction).

Records use `submission_id` as the dedup key, so re-sending the same `submission_id` updates the existing record instead of creating a duplicate. See [Feedback Records](/unify-feedback/feedback-records).

## Survey field mapping

For Formbricks Surveys, each question type is translated into the matching Hub `field_type`:

- Single-select, multi-select, dropdown → `categorical`
- NPS → `nps`
- Rating → `rating`
- CSAT → `csat`
- CES → `ces`
- Free text → `text`
- Number → `number`
- Date → `date`
- Boolean / consent → `boolean`
