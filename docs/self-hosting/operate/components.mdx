Formbricks runs several services. Use the [released Helm chart](https://github.com/formbricks/formbricks/tree/stable/charts/formbricks)
or [Compose file](https://github.com/formbricks/formbricks/blob/stable/docker/docker-compose.yml)
as the authoritative inventory of image versions for your release.

## Runtime inventory

| Component | Purpose | Image source / configuration |
| --- | --- | --- |
| Formbricks app | UI, APIs, surveys and in-process BullMQ workers | `ghcr.io/formbricks/formbricks`; `deployment.image` |
| Formbricks Hub API and worker | Feedback ingestion and PostgreSQL-backed asynchronous jobs | `ghcr.io/formbricks/hub`; `hub.image` |
| Cube | Analytics queries and release-matched data models | `ghcr.io/formbricks/cube`; `cube.image` |
| PostgreSQL | Application and Hub data | Bundled `pgvector/pgvector`, or managed PostgreSQL with required extensions |
| Redis / Valkey | App queues, cache and coordination | Released chart/Compose dependency, or managed service |
| SpiceDB | Permission decisions; dedicated PostgreSQL database and login | AuthZed SpiceDB; `authzed` values and operator-managed image |
| SpiceDB operator | Kubernetes datastore migrations and SpiceDB rollout | Released `spicedb-operator` dependency; one owner per cluster |
| Object storage | Uploads, images and other files | S3-compatible service; optional bundled RustFS on Docker |
| Edge protection | TLS, routing and rate limits | Envoy Gateway, one-click Traefik, or equivalent platform protection |

Preparation, application migrations, Hub migrations and datastore bootstrap also run short-lived
containers or Jobs. Include their images in registry allowlists. Docker uses a `spicedb-migrate`
service instead of the Kubernetes operator.

Optional services include embeddings (TEI), taxonomy and an LLM runtime. Enable them only when needed;
see [AI configuration](/self-hosting/configuration/ai-features). Their versions are independent of the app.

## Who owns what

| Owner | Responsibility |
| --- | --- |
| Your platform team | Datastores, backups, TLS, secret delivery, CRDs, capacity and recovery |
| Deployment tooling | Maintenance, stopping writers, configuration, ordered rollout and restart |
| Formbricks release image | Application migrations and permission preparation/checks |
| SpiceDB operator or datastore operator | SpiceDB datastore schema migrations and runtime health |

Managed services replace bundled infrastructure, not these responsibilities. Keep application and
SpiceDB credentials separate. Mount database-administrator credentials only in bootstrap jobs that
need them, never in the app. Keep permission traffic private and use TLS for external endpoints.

## Record the deployed inventory

Before an upgrade, render the selected chart or inspect the resolved Compose images privately.
Record app/chart versions, dependency images and enabled services with your deployment configuration.
Do not put expanded Secrets or credentials in shared logs.

For rollout and scaling, see [architecture](/self-hosting/setup/cluster-setup).
