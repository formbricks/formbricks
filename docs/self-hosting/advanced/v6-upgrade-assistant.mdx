Formbricks v6 uses SpiceDB for authorization decisions. Existing data must first be projected from Formbricks
PostgreSQL while a release-matched bridge keeps the v5 authorization behavior authoritative. The signed
upgrade assistant provides a read-only preflight for Docker Compose and Helm, and an automated receipt-backed
cutover for installations using bundled Docker PostgreSQL.

<Warning>
  Back up the Formbricks PostgreSQL database and the installation directory before executing the upgrade. Do
  not use `docker compose down -v`: the PostgreSQL volume is the source of product and authorization data.
</Warning>

## Download and verify the release bundle

Download these assets from the same [Formbricks v6 release](https://github.com/formbricks/formbricks/releases):

- `formbricks.sh`, `formbricks-upgrade-assistant`, `formbricks-upgrade-manifest.json`
- `formbricks-authzed-overlay.yml`, `authzed-postgres-bootstrap.sh`
- `formbricks-upgrade-<version>.tgz` for Helm
- `formbricks-upgrade-checksums.txt`, `formbricks-upgrade-checksums.sigstore.json`

Do not mix releases. Install [cosign](https://docs.sigstore.dev/cosign/system_config/installation/), then verify
the release identity and every downloaded file:

```bash
cosign verify-blob \
  --bundle formbricks-upgrade-checksums.sigstore.json \
  --certificate-identity-regexp \
    '^https://github\.com/formbricks/formbricks/\.github/workflows/.+@refs/(heads/main|tags/.+)$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  formbricks-upgrade-checksums.txt

sha256sum --check formbricks-upgrade-checksums.txt
chmod 0755 formbricks-upgrade-assistant
chmod 0755 formbricks.sh
```

On macOS, use `shasum -a 256 --check formbricks-upgrade-checksums.txt`. The signed manifest binds the
operation to distinct immutable bridge and target images, their embedded runtime contracts, and the exact
multi-architecture `pgvector/pgvector` and `authzed/spicedb` image digests used during the upgrade. The
assistant rejects mutable or unexpected image references and installs the signed references into the Docker
environment before Compose renders the upgrade overlay.

## Run the read-only preflight

Point `--path` to the Compose file, its directory, or the parent of a one-click `formbricks/` directory:

```bash
./formbricks-upgrade-assistant preflight \
  --manifest ./formbricks-upgrade-manifest.json \
  --path ./formbricks
```

If a customized mutable image does not expose its version, supply the version you independently verified:

```bash
./formbricks-upgrade-assistant preflight \
  --manifest ./formbricks-upgrade-manifest.json \
  --path ./formbricks \
  --current-version 5.4.3
```

Preflight renders configuration and reads runtime metadata only. It never pulls images, runs migrations,
changes files, starts SpiceDB, or stops Formbricks. `ready` means the source is supported; it does not mean
the relationship graph has already been built.

For Helm, select the release explicitly when the current context contains more than one Formbricks release:

```bash
./formbricks-upgrade-assistant preflight \
  --manifest ./formbricks-upgrade-manifest.json \
  --install-type helm \
  --helm-release formbricks \
  --namespace formbricks
```

Helm execution remains an explicit temporary-chart procedure. The assistant's `execute` command does not
mutate Kubernetes resources.

## Execute a Docker or one-click upgrade

The automated executor currently supports installations using the bundled `postgres` service. From the
directory that contains the one-click `formbricks/` folder, run the verified updater and bundle:

```bash
/absolute/path/to/the/verified-release-bundle/formbricks.sh update \
  --v6-upgrade-bundle /absolute/path/to/the/verified-release-bundle \
  --yes
```

If version detection was not possible during preflight, add `--current-version 5.4.3`. Standard Docker Compose
operators can invoke the verified assistant directly:

```bash
./formbricks-upgrade-assistant execute \
  --manifest ./formbricks-upgrade-manifest.json \
  --overlay ./formbricks-authzed-overlay.yml \
  --bootstrap-helper ./authzed-postgres-bootstrap.sh \
  --path /absolute/path/to/the/installation \
  --yes
```

The one-click updater re-verifies the signed checksum set before delegating. Execution then:

1. Preserves the customer-owned `docker-compose.yml` and backs up `.env`.
2. Installs the signed, permanent `formbricks-authzed-overlay.yml` and database bootstrap helper.
3. Generates stable AuthZed secrets, starts private SpiceDB, and runs bridge-compatible migrations.
4. Starts the immutable legacy-authoritative bridge and checks its embedded runtime contract.
5. Applies the canonical schema, drains the outbox, reconciles relationships, and creates a database receipt.
6. Stops only Formbricks, activates the receipt, starts the immutable v6 candidate, checks it, and finalizes.

The base Compose file is never rewritten. Keep the overlay beside it for all later Compose operations:

```bash
docker compose -f docker-compose.yml -f formbricks-authzed-overlay.yml ps
```

The overlay requires `AUTHZED_POSTGRES_BOOTSTRAP_IMAGE_REF` and `SPICEDB_IMAGE_REF`. The assistant writes the
release-reviewed immutable values from the signed manifest; do not replace them with tags during the cutover.

For a later v6 release, set `FORMBRICKS_IMAGE_REF` in `.env` to that release's reviewed immutable image digest
and run the normal `./formbricks.sh update`. The updater runs migrations through the overlaid application
service even when the preserved v5 Compose file has no `formbricks-migrate` service.

SpiceDB remains private on the Compose network. The executor stores sanitized progress in
`.formbricks-v6-upgrade-state.json` and detailed local command output in `formbricks-v6-upgrade.log`; both use
mode `0600`. It never emits credentials in its JSON result.

## Failure and rollback behavior

Before activation, a failure leaves or restores the bridge. After activation, a failed candidate start,
runtime check, or finalization fences writes, restores the exact signed bridge, switches database authority
back to legacy, and returns `candidate_failed_rolled_back`.

If the host or shell stops during the cutover, rerun the same signed command. A recorded post-activation run
is conservatively rolled back before another attempt. Do not delete the state file, overlay, bridge image, or
either database. `activation_state_requires_manual_recovery` means the local receipt cannot be matched safely;
keep Formbricks quiesced and contact support with the sanitized state and log files.

## Results

Preflight prints one JSON object and exits `0` for `ready` or `not_required`, `2` for a blocked prerequisite,
and `64` for invalid arguments. Execute exits `0` only for `status: "upgraded"`. A blocked or rolled-back
execution exits non-zero. Raw command errors, tokens, database URLs, relationship identifiers, and filesystem
paths are not written to standard output.

External PostgreSQL and Helm upgrades require the explicit operator runbook because the assistant cannot
derive or install their database credentials safely. Continue with
[AuthZed Operations](/self-hosting/advanced/authzed-operations) for the Helm temporary chart, backups,
validation, and recovery procedures.
