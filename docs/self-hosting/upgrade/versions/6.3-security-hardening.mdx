**Applies to:** the upgrade to 6.3.

## Auth base URL falls back to `WEBAPP_URL`

Formbricks resolves the URL that sign-in links, OAuth redirects and the cross-site request check are built from as
`BETTER_AUTH_URL`, then `NEXTAUTH_URL`, then (new in 6.3) `WEBAPP_URL`. `WEBAPP_URL` also joins the trusted origins.

Before 6.3, an instance that set only `WEBAPP_URL` took that URL from each request's `Host` header, so a proxy that
forwards any `Host` let the caller choose it. Nothing to do if you set `BETTER_AUTH_URL` or `NEXTAUTH_URL`. If you set
neither, check that `WEBAPP_URL` is the public URL your users sign in on.

## Integration tokens are encrypted at rest

From 6.3, Formbricks encrypts the Slack, Google Sheets and Airtable access and refresh tokens with `ENCRYPTION_KEY`
(Notion's were already encrypted). Tokens stored by an earlier version keep working and are encrypted the next time
the integration is saved.

- **Rolling back is one-way for these integrations.** A version before 6.3 can't read an encrypted token. If you
  go back after 6.3 has saved one, reconnect Slack, Google Sheets and Airtable in each workspace that uses them.
- **Changing `ENCRYPTION_KEY` disconnects them.** A token encrypted with the old key can't be read with the new
  one. That integration stops sending responses and reads as having no token, and the log shows
  `Integration credentials no longer decrypt` with its id. The workspace's other integrations keep working.
  Reconnect each one that is affected. Notion tokens and other data encrypted with the key stop working too, so
  keep `ENCRYPTION_KEY` unchanged unless you plan to reconnect.
- **A wrong key by mistake is recoverable.** Editing an affected integration's settings keeps the stored token as it
  is, so putting the previous `ENCRYPTION_KEY` back restores the integration without reconnecting.

## v1 management API list limits

The v1 management list endpoints (surveys, responses, action classes, contacts, contact attributes, contact
attribute keys and webhooks) return at most 250 items per request. A request with `limit` above 250 now gets
`400 Bad Request` instead of a result, and a request without `limit` gets the endpoint's default page. To read more,
page through with `limit` of 250 or less and `skip` (`offset` on surveys).
