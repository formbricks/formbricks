**Applies to:** installations entering or updating within 5.4, both editions and deployment methods.
The base-release steps apply when crossing 5.4.0; for later updates within 5.4, review the [patch actions](#patch-actions).
**Upgrade from:** the latest 5.3 patch (5.3.5). Skipping a minor version is not supported; see [Upgrade paths](/self-hosting/upgrade/paths).

## Before

| Who needs to act | Action |
| --- | --- |
| Every installation | Preserve secrets and configure `WEBAPP_URL` for migrations, including existing MCP OAuth clients. |
| Large response tables | [Build and validate the response index](/self-hosting/upgrade/versions/5.4-database) ahead of maintenance, or allow time for its blocking build. |
| Feedback APIs using keys | [Review delete permissions and shared datasets](/self-hosting/upgrade/versions/5.4-api-permissions). |
| SSO/MCP users | [Review authentication changes](/self-hosting/upgrade/versions/5.4-authentication); test existing-user sign-in and token renewal. |
| Bundled dependencies | [Update Valkey and review Cube/Envoy changes](/self-hosting/upgrade/versions/5.4-runtime) for the selected patch. |

### Patch actions

Apply each change you cross on this release line, even when installing a later patch.
These entries do not add intermediate installation stops.

| First affected patch | Additional action |
| --- | --- |
| 5.4.1 | Microsoft multi-tenant SSO fixes; use a concrete Entra tenant for full token verification where appropriate. |
| 5.4.3 | Envoy Gateway/CRD update and controller values move; coordinate cluster ownership. |
| 5.4.4 | Bundled storage setup switches its helper client to RustFS CLI. Preserve existing MinIO/S3 data and settings. |
| 5.4.5 | [5.4.5: Cube image migration](/self-hosting/upgrade/versions/cube). Copy the whole service, not only its image. |
| 5.4.6 | Nothing extra. See [5.4.6](/platform/changelog#release-5-4-6). |
| 5.4.7 | [5.4.7: Security updates](/self-hosting/upgrade/versions/2026-10-security-patches): Redis CA, Hub/enrichment and MCP batches. |
| 5.4.8 | [5.4.8: Security updates](/self-hosting/upgrade/versions/2026-10-27-patches): outgoing-email limits. |
| 5.4.9 | None. See [5.4.9](/platform/changelog#release-5-4-9). |

Read the [published patch notes](https://github.com/formbricks/formbricks/releases) for other fixes too.
A patch without an additional row still needs the standard checks.

## During

Use the [4.x/5.x maintenance procedure](/self-hosting/upgrade/legacy). Keep traffic closed and writers
stopped. Run app migrations before Hub migrations; inspect their exit status. The response-index build
can exceed the historical Compose migration timeout. Do not continue over a failed or invalid index.

## After

- Verify existing password/SSO accounts, 2FA and MCP clients, including token renewal after sign-out.
- Check dashboard queries, feedback mutations with their intended API keys, and Hub job delivery.
- Confirm migrations and the response index completed; run the [shared acceptance checks](/self-hosting/upgrade/rehearse#acceptance-at-every-stop).

## Recovery

Application schema changes are additive relative to 5.3, but Hub/dependency updates require their own
recovery assessment. After a rollback to 5.3, accounts created there may need the
[issuer repair before rolling forward](/self-hosting/upgrade/versions/5.4-database#recovery-across-5-4).
Use [coordinated restore](/self-hosting/operate/backup-restore) when required.

[5.4 patches](https://github.com/formbricks/formbricks/compare/5.4.0...5.4.9).
