## Before

- Applies to self-hosted 6.0 → 6.1 upgrades. From v5, complete the [6.0 prerequisites](/self-hosting/upgrade/versions/6.0) first.
- The [published release notes](/platform/changelog) identify **6.0.2 → 6.1.0** as the tested pair.
  This is reported release evidence, not a runtime rehearsal of your deployment.
- Plan maintenance for respondent traffic, APIs and admin access; pause background workers.
- Read the integration changes below before scheduling the upgrade.

## During

Use [Kubernetes](/self-hosting/upgrade/kubernetes) or [Docker Compose](/self-hosting/upgrade/docker).
This release changes the permission schema. Review its current digest before preparation; do not bypass
the mismatch check. The [online mode](/self-hosting/configuration/online-upgrade) remains under validation.

## After

Verify permissions, respondent submission, a scoped API key, background delivery and dashboard charts.
Regenerate encrypted single-use links after deployment. Enable survey visibility only after its checks pass.
Use [coordinated recovery](/self-hosting/operate/backup-restore) if repair cannot complete.

## Integration changes requiring action

These are historical compatibility exceptions; the [compatibility commitment](/self-hosting/advanced/release-maintenance-policy#integration-compatibility)
does not erase them.

- Ending-card URLs require a dotted hostname, `localhost` or an IP. A single-label host returns `400` on save.
- New hidden fields cannot share a question name on v1 survey creation/update (`400`).
- Survey creation/copying returns `422 workspace_survey_limit_reached` at the configured workspace limit.
  Review `SURVEY_WORKSPACE_LIMIT` before upgrading; the default is `10000`, including archived surveys.
- Helm custom images must support the new container security settings. Review the [6.1 changelog](/platform/changelog).
