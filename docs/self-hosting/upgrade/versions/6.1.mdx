**Upgrade from:** the latest 6.0 patch. Skipping 6.0 is not supported; see [Upgrade paths](/self-hosting/upgrade/paths).
**Downtime:** a maintenance window. **Applies to:** all editions and setups.

## What changes

- Survey visibility: organizations can restrict who sees each survey and its responses. It's off until you [turn it on](/self-hosting/upgrade/versions/6.1-visibility).
- Encrypted single-use links created before 6.1 stop working and must be [created again](/self-hosting/upgrade/versions/6.1-single-use-links).
- The permission schema changes, so permission preparation is needed.
- New database indexes are built, and Embedded Data and survey ownership are backfilled during the migration.
- Some API requests are validated more strictly (see [integration changes](#integration-changes-requiring-action)).

## Before you upgrade

| Who | What to do |
| --- | --- |
| Everyone | Plan a maintenance window. The migration builds indexes and backfills data, so allow extra time and free disk space on large databases. |
| API integrations | Check the [integration changes](#integration-changes-requiring-action) below. |
| Single-use link users | Plan to [create new encrypted single-use links](/self-hosting/upgrade/versions/6.1-single-use-links) after the upgrade. |
| Docker Compose and one-click | Add the Hub worker if it's missing, and use the 6.1 Cube model files. See [runtime changes](/self-hosting/upgrade/versions/6.1-runtime). |
| Kubernetes with chart-managed Envoy | Use your own Redis or Valkey for Envoy; the bundled Envoy Redis images are no longer available. See [Envoy Redis images](/self-hosting/upgrade/versions/6.1-runtime#envoy-redis-images). |
| Kubernetes with custom images or taxonomy settings | Check the [security contexts and taxonomy timeouts](/self-hosting/upgrade/versions/6.1-runtime#helm-security-contexts-and-taxonomy-timeouts). |

## Upgrade

Follow the runbook for your setup: [Kubernetes](/self-hosting/upgrade/kubernetes),
[Docker Compose](/self-hosting/upgrade/docker) or [one-click](/self-hosting/upgrade/one-click).
Because the permission schema changes, permission preparation asks you to confirm the change. See
[schema changes](/self-hosting/upgrade/prepare) in permission preparation.

<span id="after" />

## Check it worked

- Users can sign in, including existing SSO users, and see the surveys they should.
- You can submit a survey response, and API keys work for what they're allowed to do.
- Webhooks and workflows run, and dashboard charts load.
- Old and new file uploads open.
- Then create new encrypted single-use links, and turn on survey visibility if you want it.

Also do the [checks after the upgrade](/self-hosting/advanced/upgrade#after-the-upgrade).

<span id="recovery" />

## If something goes wrong

Keep the maintenance window open. If you can't fix the problem, restore the app database, Hub data, SpiceDB and
your configuration from the backup; see [backup and restore](/self-hosting/operate/backup-restore). Don't go back to
an older version just to make old single-use links work again: that reopens the security issue 6.1 fixes.

## Integration changes requiring action

6.1 is a minor release, but these changes can affect existing integrations.

- Regenerate [encrypted single-use links](/self-hosting/upgrade/versions/6.1-single-use-links).
- Review [Helm security contexts and taxonomy timeouts](/self-hosting/upgrade/versions/6.1-runtime#helm-security-contexts-and-taxonomy-timeouts)
  if you use custom images or override taxonomy settings.

**API**

* **Ending-card URLs need a real host.** `buttonLink` and `url` on ending cards (v1, v2 and v3 survey create and update) must use a hostname with a dot (`intranet.example.com`), `localhost` or an IP address. A host like `http://intranet` now returns 400. Existing surveys keep loading; the rule applies when they are next saved ([#9399](https://github.com/formbricks/formbricks/pull/9399))
* **Hidden fields can't share a name with a question.** Adding one on `POST` or `PUT /api/v1/management/surveys` returns 400. Existing surveys keep saving ([#9467](https://github.com/formbricks/formbricks/pull/9467))
* **New survey limit per workspace.** `SURVEY_WORKSPACE_LIMIT` (a number, default `10000`, archived surveys included) caps the surveys in one workspace. Creating or copying a survey past it returns `422 workspace_survey_limit_reached` on v1 and v3. Raise it before upgrading if a workspace is close ([#9412](https://github.com/formbricks/formbricks/pull/9412))
