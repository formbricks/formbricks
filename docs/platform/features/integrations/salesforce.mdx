<Note>
  There is no native Salesforce integration yet. Connect Formbricks to Salesforce with Make (recommended), n8n, or a custom webhook.
</Note>

## Prerequisites

- A Formbricks survey that collects email addresses
- A Salesforce edition with API access (Enterprise, Unlimited, Developer, or Professional with the API add-on)
- A Make or n8n account, unless you build a custom webhook

---

## Method 1: Make.com (Recommended)

Make is a registered Salesforce app, so you only need to log in and click **Allow**. No Salesforce app setup is required.

<Steps>
  <Step title="Set Question IDs">
    Give each question a meaningful `questionId` so mapping is easier. These can only be changed before publishing; for a published survey, duplicate it first.

    ![Update Question ID](/images/platform/features/integrations/make/update-question-id.webp)
  </Step>
  <Step title="Add the Formbricks Trigger">
    In a new [Make](https://make.com) scenario, add **Formbricks** → **Watch Response Finished**. Click **Create a webhook**, enter your API host (default `https://app.formbricks.com`) and [API key](/api-reference/rest-api#how-to-generate-an-api-key), and select your survey.

    ![Search Formbricks](/images/platform/features/integrations/make/search-formbricks.webp)
    ![Enter API Key](/images/platform/features/integrations/make/enter-api-key-and-host.webp)
  </Step>
  <Step title="Add the Salesforce Module">
    Add **Salesforce** → **Create a Record**. Next to **Connection**, click **Add**, log in, and click **Allow**. Set **Type** to **Contact** for existing customers, or **Lead** for new prospects.
  </Step>
  <Step title="Map Fields">
    | Salesforce Field | Formbricks Field |
    | ---------------- | ---------------- |
    | Email | `data.email` |
    | First Name | `data.firstName` |
    | Last Name (required) | `data.lastName` |
    | Account | Optional, but Contacts without one are private to their owner |
    | Custom Field | Any `data.*` or `meta.*` field |
  </Step>
  <Step title="Avoid Duplicates">
    Salesforce doesn't match on email by default. Add a **Search Records** module before the create step and route existing matches to **Update a Record**.
  </Step>
  <Step title="Test and Activate">
    Submit a test response, confirm the record in Salesforce, and turn on the scenario.

    ![Formbricks to Salesforce Scenario](/images/platform/features/integrations/make/salesforce-scenario.webp)
  </Step>
</Steps>

## Method 2: n8n

The built-in Salesforce node works on n8n Cloud and self-hosted, but needs a Salesforce app for OAuth login.

<Steps>
  <Step title="Add the Formbricks Trigger">
    Add the **Formbricks** trigger node, connect your API key and host, select **Response Finished**, and choose your survey.

    ![Add Formbricks Trigger](/images/platform/features/integrations/n8n/add-formbricks-trigger.webp)
  </Step>
  <Step title="Create a Salesforce App">
    In Salesforce, go to **Setup** → **App Manager** → **New External Client App** (or **New Connected App**). Enable OAuth, set the callback URL n8n shows you (`https://<your-n8n-domain>/rest/oauth2-credential/callback`), and add the `api` and `refresh_token, offline_access` scopes. Copy the Consumer Key and Secret.
  </Step>
  <Step title="Add the Salesforce Node">
    Choose **Contact** → **Create or Update**, create a Salesforce OAuth2 credential with the key and secret, and click **Connect my account**.
  </Step>
  <Step title="Map Fields">
    Create or Update needs an external ID field to match on, such as a custom `Email__c` field on Contact marked as External ID and Unique.

    ```
    Email: {{ $json.data.email }}
    First Name: {{ $json.data.firstName }}
    Last Name: {{ $json.data.lastName }}
    ```
  </Step>
  <Step title="Test and Activate">
    Click **Listen for event**, submit a test response, confirm the record in Salesforce, and activate the workflow.
  </Step>
</Steps>

## Method 3: Custom Webhook (Advanced)

Use this only if you want to avoid Make or n8n. Your handler authenticates with the OAuth 2.0 Client Credentials Flow.

### Set Up an External Client App

<Steps>
  <Step title="Create the App">
    Go to **Setup** → **App Manager** → **New External Client App**, and set Distribution State to **Local**.
  </Step>
  <Step title="Configure OAuth">
    Enable OAuth, use any callback URL (e.g. `https://login.salesforce.com/services/oauth2/callback`), and select **only** the `api` scope. Enable **Client Credentials Flow** and save.
  </Step>
  <Step title="Set the Run As User">
    In **External Client Apps Manager** → your app → **Policies**, set **Run As** to an active, full-license user with **API Enabled** and create/edit access on Contact.
  </Step>
  <Step title="Copy the Credentials">
    On the **Settings** tab, click **Consumer Key and Secret** and copy them. Changes can take a few minutes to apply.
  </Step>
</Steps>

See [Salesforce's Client Credentials Flow guide](https://help.salesforce.com/s/articleView?id=xcloud.configure_client_credentials_flow_for_external_client_apps.htm) for details.

### Build the Handler

<Steps>
  <Step title="Create a Formbricks Webhook">
    Go to **Configuration** → **Integrations** → **Manage Webhooks** → **Add Webhook**, enter your endpoint URL, select **Response Finished**, and choose your surveys.
  </Step>
  <Step title="Write the Handler">
    1. Read the answers from `data.data` (keyed by `questionId`).
    2. Get a token: `POST https://YOUR_DOMAIN.my.salesforce.com/services/oauth2/token` with `grant_type=client_credentials`.
    3. Create the Contact: `POST /services/data/vXX.0/sobjects/Contact`.
    4. To avoid duplicates, query by email first and `PATCH` any match, or upsert via an external ID: `PATCH /sobjects/Contact/Email__c/jane@example.com`.

    For signature verification, see [Webhooks](/platform/features/integrations/webhooks).
  </Step>
  <Step title="Deploy and Test">
    Deploy the handler to a public URL, submit a test response, and confirm the record in Salesforce.
  </Step>
</Steps>

## Troubleshooting

**No record created**
- Check that you're mapping the correct email `questionId`.
- Contacts require `LastName`. Your org may also require an Account via a validation rule.

**Duplicate records**
- Add a search-then-update step, or upsert on an external ID.

**Authentication errors (Method 3)**
- `no client credentials user enabled`: set a valid **Run As** user under **Policies**.
- `no valid scopes defined`: make sure the `api` scope is selected; Client Credentials ignores `full` and `refresh_token`.
- Expired token or blocked IP: request a new token on 401, and check Trusted IP Ranges.

**Webhook not firing**
- Check the URL is public, **Response Finished** is selected, and the survey is linked.
