<Update label="6.1.0" description="19 October 2026">
### Overview

Formbricks 6.1 adds survey visibility, so organizations can restrict who sees each survey and its responses, and brings dark mode and Custom CSS to surveys. It also adds Qualtrics survey import from .qsf files, Embedded Data V2 with a shared field library, the v3 Responses API with matching MCP tools, and new chart types and filters.

Self-hosters: follow the [upgrade steps](/self-hosting/advanced/upgrade), and see the [migration guide](/self-hosting/advanced/migration#v6) for details on each change. The tested upgrade pair for this release is **6.0.2 → 6.1.0**. Kubernetes installs can opt into the [online upgrade mode](/self-hosting/configuration/online-upgrade) instead of a maintenance window; it is still under validation, so the maintenance path remains the default.

Formbricks 6.1 receives bug fixes and security fixes until **19 January 2027**.

### ⚠️ Breaking changes

6.1 is a minor release. It has no major breaking changes, only the smaller ones below, each of which affects a specific setup. As with every upgrade, follow the [upgrade steps](/self-hosting/advanced/upgrade), which include a short maintenance window.

**Self-hosting**

* **Encrypted single-use links stop working.** Links created before 6.1 with URL encryption on (the default) are rejected after the upgrade. Re-create and re-send them. If you need more time, set `SINGLE_USE_LEGACY_UNSIGNED_UNTIL` to a date in `YYYY-MM-DD` format, for example `2026-11-15`: old links keep working until 00:00 UTC on that day. Use it only on an instance that serves a single organization, because it re-opens the issue this release fixes. Unencrypted links and custom single-use IDs are not affected ([#9131](https://github.com/formbricks/formbricks/pull/9131))
* **Helm: the web container is locked down.** It now runs with a read-only root filesystem, as non-root user `1001`, with all Linux capabilities dropped. This only affects custom images or sidecars that write inside the container: mount a writable path with `deployment.extraVolumes` and `deployment.extraVolumeMounts`, or set `deployment.containerSecurityContext.readOnlyRootFilesystem: false`. If you set `deployment.securityContext.runAsUser`, move it to `deployment.containerSecurityContext.runAsUser`, which now takes precedence ([#9450](https://github.com/formbricks/formbricks/pull/9450))
* **Helm: AuthZed hooks run as user `1001`.** If your custom image needs another user, set `authzed.initialization.securityContext.runAsUser` ([#9516](https://github.com/formbricks/formbricks/pull/9516))
* **Helm: taxonomy timeout overrides are validated.** With `taxonomy.enabled=true`, rendering fails unless `taxonomy.terminationGracePeriodSeconds` is at least `taxonomy.runDeadlineSeconds` + 30, and `taxonomy.hubStaleRunTimeoutSeconds` is greater than `taxonomy.runDeadlineSeconds`. The defaults (900, 930 and 1800 seconds) pass ([#9451](https://github.com/formbricks/formbricks/pull/9451))

**API**

* **Ending-card URLs need a real host.** `buttonLink` and `url` on ending cards (v1, v2 and v3 survey create and update) must use a hostname with a dot (`intranet.example.com`), `localhost` or an IP address. A host like `http://intranet` now returns 400. Existing surveys keep loading; the rule applies when they are next saved ([#9399](https://github.com/formbricks/formbricks/pull/9399))
* **Hidden fields can't share a name with a question.** Adding one on `POST` or `PUT /api/v1/management/surveys` returns 400. Existing surveys keep saving ([#9467](https://github.com/formbricks/formbricks/pull/9467))
* **New survey limit per workspace.** `SURVEY_WORKSPACE_LIMIT` (a number, default `10000`, archived surveys included) caps the surveys in one workspace. Creating or copying a survey past it returns `422 workspace_survey_limit_reached` on v1 and v3. Raise it before upgrading if a workspace is close ([#9412](https://github.com/formbricks/formbricks/pull/9412))
