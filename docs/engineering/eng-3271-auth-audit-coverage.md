# ENG-3271: authentication audit boundaries

Implements the authentication slice of the [ENG-2801 coverage matrix](https://linear.app/formbricks/document/eng-2801-product-wide-audit-log-coverage-matrix-2026-09-17-bac459651591).

## Event contract

`security-audit.ts` emits through the real Enterprise event validator and logger, after the operation settles. Account events explicitly carry `scope: global` and `organizationId: global`. Invite and SSO membership events use the stored organization; PIN events resolve the survey's organization. Unresolved tenant attribution is explicitly `unknown`. No tenant is inferred from an account's memberships.

Each event carries a server-generated request ID, unique event ID, source, operation, principal, target and outcome. Nested native calls share their server action's request ID. The action is `securityOperation` with an allowlisted `changes.operation`, except preserved authentication actions and `jwtTokenCreated`. Principals come from verified sessions, signed and unexpired 2FA challenges, successfully verified email links, or validated OAuth grants. A submitted email is never an authenticated user; credential failure identifiers are hashed and typed `anonymous`.

Summaries contain row IDs, mutation kinds, changed field names and security-policy boolean transitions. They never include profile values, passwords/hashes, factors, backup codes, OAuth secrets, redirect/query payloads, survey responses, PINs or email bodies. Issued tokens/codes are represented by SHA-256 fingerprints. Invite/SSO grants carry organization/team membership identifiers and roles.

## Outcome rules and deliberate exclusions

A successful HTTP response alone is insufficient: no changed rows or granted artifact means `noop`. A later failure after committed writes means `partial`, with only observed changes listed. Missing observation data is also explicitly `partial`; it never becomes a full success. Native unique-row deletes use the adapter's atomic `consumeOne` result, preserving its void return contract while distinguishing a concurrent/no-op deletion. Batch snapshots are paginated and checked against the affected count; mismatches do not claim an exact deletion manifest. The configured Prisma adapter has transactions disabled by default, so earlier native writes remain visible on a later failure. An adapter configured for real transactions must pass `transactional: true` to publish its journal only after commit.

Ordinary reads, session expiry refresh, login timestamps, identity denormalization, verification-store housekeeping and 2FA retry counters are bookkeeping. The legacy 2FA repair only re-encodes existing factors for an already enrolled account after the password step; its upsert never replaces a concurrently created enrollment. It is suppressed because it neither grants access nor rotates a factor. Actual enrollment/rotation/disable is audited.

Native/SSO user creation and closed-signup denial remain owned by ENG-2347; mail delivery remains owned by ENG-2348. Existing signed-in, password-reset completion, account-deletion and SSO-recovery events are retained. Unconfigured administrative OAuth resource management and deployment-time resource seeding are outside this ticket's account flow. This change does not claim durable delivery, collector receipt, or complete product-wide coverage.

## Credential-failure sampling

A Redis script atomically increments the current count and selects attempts 1–3, every tenth attempt, or the first attempt at least one minute after the last selected event. Each selected event records `attemptCount`, `suppressedCount` and `windowStart`; the minute check never reads the timestamp of a merely attempted login. Real Redis tests verify counts, omission counts and concurrent selection. A production-route test verifies the first three final payloads and absence of a fourth duplicate event.

On Redis failure, every failure is emitted with `samplingUnavailable: true`: the sampler loses no events during the outage. Deliberate omissions at the end of a sampling window are not flushed as a separate event if no further attempt occurs. Thus sampled logs are not an exact total-attempt counter. Delivery remains best-effort independently of sampling.

## Verification

After building workspace dependencies, run:

```sh
pnpm --filter @formbricks/web exec vitest run modules/auth modules/ee/sso modules/ee/audit-logs modules/survey/link/actions.test.ts --coverage '--coverage.include=modules/auth/lib/**' --maxWorkers=4
pnpm --filter @formbricks/web test:integration modules/auth/invite/lib/accept-invitation.integration.test.ts modules/auth/lib/auth-failure-sampling.integration.test.ts modules/auth/lib/native-auth-audit.integration.test.ts modules/auth/lib/better-auth-observability.integration.test.ts
pnpm --filter @formbricks/web exec tsc --noEmit
```

Integration tests require the existing isolated Postgres/Redis harness (`apps/web/integration/setup.ts` and `apps/web/vitest.integration.config.mts`); never point its reset at a development or production database. Tests inspect the final logger payload, with the logger as the output boundary, and exercise real Better Auth dispatch. Database and sampling integrations use real Postgres and Redis. No browser visual QA or external log collector was exercised. No migrations, new environment variables or locale changes are required.
