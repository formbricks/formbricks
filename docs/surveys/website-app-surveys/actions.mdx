## How do Actions work?

<Steps>
  <Step title="User performs action">
    The user performs an action in your application.
  </Step>

<Step title="Formbricks widget detects action">
  The embedded widget (SDK) detects the action, if it is a [No Code
  Action](/surveys/website-app-surveys/actions#no-code-action-types) or a [Code
  Action](/surveys/website-app-surveys/actions#code-actions) that exists in the workspace.
</Step>

<Step title="Check for survey trigger">
  If a survey is set to trigger on that action, Formbricks checks if the user or visitor qualifies.
</Step>

  <Step title="Check for user or visitor qualification">
    If a Cooldown Period applies and the user or visitor was **shown** a survey inside it, this one will not be shown, to prevent survey fatigue. Three things about that gate are easy to get wrong: the interval is whatever you configured, not a fixed one; a survey can set its own, which overrides the workspace value, and a survey set to ignore the cooldown skips the check entirely; and it counts displays of **any** survey, not answers to this one — so declining to answer, or being shown a different survey, still starts the clock.

    Also, if this user or visitor has seen this specific survey before, Formbricks might not show it, depending on the survey's recontact options. See [Survey Display Logic](/surveys/website-app-surveys/survey-display-logic).

  </Step>

  <Step title="Show survey">
    If all conditions match, the survey is shown.
  </Step>
</Steps>

<Tip>
  Tying surveys to specific user actions enables **context-aware surveying**: You make sure that your user
  research is relevant to the current user context which leads to sign**ificantly higher response and
  completions rates** as well as lower survey fatigue.
</Tip>

<Note>
  **Important**: Any changes to actions, surveys, or environment configuration will take **up to 1 minute** to
  reflect in your app/website due to server-side caching. This includes new actions, modified action 
  configurations, and survey trigger updates.
</Note>

## No-code action types

No-code actions are detected by the SDK without any code on your side.

<Note>
  No Code Actions are **not available for surveys in mobile apps**. No Code Action tracking is heavily
  dependent on JavaScript and most mobile apps are compiled into a different programming language. To track
  user actions in mobile apps use [Code Actions](/surveys/website-app-surveys/actions#code-actions).
</Note>

Ask your agent to list the actions of a workspace with `list_action_classes` over [MCP](/platform/mcp/overview), or with `GET /api/v3/action-classes`. Every action in the workspace is listed, no-code and code alike.

There are five types of no-code action.

### 1. Click

Fires when a user clicks a specific element. Define the element by its **CSS Selector**, its **Inner Text**, or both — with both switched on, the click has to match both to count.

- **Inner Text**: matches the text of the clicked element, such as a button label.

- **CSS Selector**: matches a class, an id, or any other CSS selector. See [CSS Selector](#css-selector) below for how to write one.

#### CSS Selector

A CSS selector tells Formbricks which element to watch. The symbol in front of the name says what kind of name it is:

| To match an element by… | Write                   | Matches                          |
| ----------------------- | ----------------------- | -------------------------------- |
| its id                  | `#signup-button`        | `<button id="signup-button">`    |
| its class               | `.btn-primary`          | `<button class="btn-primary">`   |
| several classes at once | `.btn.btn-primary`      | an element that has both classes |
| element type and class  | `button.btn-primary`    | only buttons with that class     |
| an attribute            | `[data-track="signup"]` | `<button data-track="signup">`   |

<Warning>
  Without `#` or `.`, the name is read as an element type. `signup-button` matches a `<signup-button>` tag, not an element with that id or class. If your page has no such tag, the action saves but cannot trigger.
</Warning>

Chain several parts without spaces to make a selector more specific, as in `button.btn-primary.large`. A click on an icon or label inside a matched element counts as a click on that element.

To find the id or class of a button on your site:

<Steps>
  <Step title="Inspect the element">
    Right-click the button in your browser and choose **Inspect**.
  </Step>

  <Step title="Read its id or class">
    In the highlighted HTML, look for `id="…"` or `class="…"`. Prefer an id: it is unique on the page.
  </Step>

  <Step title="Add the symbol">
    Put `#` in front of an id, or `.` in front of a class name, and paste it into the CSS Selector field. A `class` attribute with several names separated by spaces holds several classes: join the ones you want with dots, as in `.btn.btn-primary`.
  </Step>
</Steps>

### 2. Page View

Fires when a user opens a page. On its own it fires on every page; combine it with a page filter to narrow it down.

### 3. Exit Intent

Fires when a user looks about to leave — the pointer leaves the viewport. It is how you catch someone before they abandon a form.

### 4. 50% Scroll

Fires once a user has scrolled halfway down a page. A rough proxy for "read it".

### 5. Time on Page

Fires after a user has stayed on a page for a number of seconds that you set.

### Page filter

Every no-code action can be limited to certain pages. Leave it on **On all pages**, or switch to **Limit to specific pages** and add one or more URL rules:

- **exactMatch**: Triggers the action when the URL exactly matches the specified string.

- **contains**: Activates when the URL contains the specified substring.

- **startsWith**: Fires when the URL starts with the specified string.

- **endsWith**: Executes when the URL ends with the specified string.

- **notMatch**: Triggers when the URL does not match the specified condition.

- **notContains**: Activates when the URL does not contain the specified substring.

- **matchesRegex**: Activates when the URL matches the pattern from the specified string.

## Triggering a survey with an Action

An action does nothing until a survey listens for it. An app survey lists the actions it triggers on as `distribution.triggers[].actionClassId` in its survey document; any one of them is enough to show it. Ask your agent to set the triggers when it creates or patches the survey, using the IDs from `list_action_classes`. To show it only on certain pages, visits or devices when the action fires, add [show conditions](/surveys/website-app-surveys/show-conditions) to the same survey.

## Code actions

For more granular control, fire an action directly from your code. A code action is identified by its key, which is the string your code sends:

```javascript
formbricks.track("Button Clicked");
```

Here is an example of how to fire an action when a user clicks a button:

```javascript
const handleClick = () => {
  formbricks.track("Button Clicked");
};

return <button onClick={handleClick}>Click Me</button>;
```

The key has to match the key of a code action that exists in the workspace, and a survey has to list that action as a trigger before anything is shown.
