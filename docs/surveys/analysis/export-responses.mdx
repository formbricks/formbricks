The **Export** button on the Summary and Responses tabs opens one modal for every export. It always opens with the default settings and does not remember what you chose last time.

There are two kinds of export:

| | Standard export | Analysis export |
| --- | --- | --- |
| For | Reading and sharing responses | Statistics tools such as SPSS, Excel and Power BI |
| Settings | The defaults of the modal | Anything else: codes for questions or answers, any analysis option, or the SPSS syntax file |
| Columns | One column per question, named `1. Question text`, plus an `- Option ID` column for choice questions | One column per question, named by its [question code](/surveys/analysis/question-codes) (`q1`, `q5_1`) |
| Answers | The text the respondent saw | Answer codes, text, or both |
| Files | A CSV file, or an Excel file with one sheet named `Sheet1` | An Excel workbook with several sheets, or a zip of CSV files and an SPSS syntax file |
| Low quality responses | Included | Left out by default |

The Standard export is the file Formbricks has always produced, so pipelines that read it keep working. It is plain UTF-8 text without a byte-order mark and with `\n` line breaks.

<Note>
  Anyone who can read a survey can export it, including read-only seats.
</Note>

## Choose what to export

<Steps>
  <Step title="Filter the responses">
    Set the filter and time range on the Summary or Responses tab first. The export contains the responses the filter matches. To export only some responses, tick their rows in the Responses table and use the export action there: it opens the same modal for the selection.
  </Step>
  <Step title="Open the Export modal">
    Select **Export**. The count line tells you how many responses are included, for example "Include 1,240 responses", and how many Low quality responses were left out.
  </Step>
  <Step title="Pick the options">
    - **Format**: CSV or Excel.
    - **Add SPSS syntax file**: CSV only. It adds a `.sps` file that reads the export into SPSS. It turns off **Text only**, because the syntax reads codes.
    - **Display questions and answers**: **Text only**, **Code only** or **Text and code**.
    - **Include columns**: choose **Select all** to add the response columns, such as timestamp, tags and Embedded Data. Block groups and ranges are not available yet.
    - **Advanced options**: further analysis options. An option can force the zip file.
  </Step>
  <Step title="Export">
    Select **Export**. A toast shows the progress, then the file downloads. If it fails, the toast offers **Try again**.
  </Step>
</Steps>

<Note>
  The export runs in the app and streams the file as it is built. You can close the modal or move between Summary and Responses while it runs. If you leave Formbricks or reload the page, the export stops and you have to start it again.
</Note>

## Files in an Analysis export

An export that has more than one file is always a zip.

| Choice | Excel | CSV |
| --- | --- | --- |
| Text only, or Code only | One data sheet, `Labels` or `Codes` | `data.csv` |
| Text and code | Two data sheets, `Labels` and `Codes` | `labels.csv` and `codes.csv` |
| Always | Sheets `Datamap` and `Unmapped values` | `datamap.csv` and `unmapped-values.csv`, all in the zip |
| SPSS syntax file | | `labels.sps` in the zip |

An Excel file is built whole in memory, so a very large export may not be offered as Excel. In that case use the zip.

<Tip>
  Every file of an Analysis export is UTF-8, so Arabic and other non-Latin text stays readable. CSV files start with a byte-order mark so that Excel and SPSS detect the encoding.
</Tip>

### What the columns hold

- The first columns are `response_id`, `language` and `outcome`. The other response columns follow if you included them.
- Each question has a column named by its question code. A matrix has one column per row, named `<code>_<row code>`.
- A **single-select** or **picture selection** question has one cell with the answer code. If the question has an **Other** option, the text typed into it goes to `<code>_text`.
- A **multi-select** question has one column per option, named `<code>_<answer code>`. A cell is `1` when the option was chosen, `0` when the question was answered without it, and blank when the question was not answered or not shown. Options added after the survey was published also get `0` for earlier responses that answered the question; the datamap notes this.
- A **ranking** question has one column per option, holding the rank the respondent gave it (`1` is first), blank if the option was not ranked.
- **Rating, NPS, CSAT and CES** questions hold the number. Number inputs are exported as numbers.
- Address, contact info, file upload, date, consent and calendar questions hold the same cell as in the Standard export, under the question code.
- Calls to action and welcome cards are left out of an Analysis export.
- **Blank always means "not asked or not answered".** There are no user-missing values. If you need codes such as `98` or `99`, add them as ordinary answer options.
- With **Text and code**, the header cell in the `Labels` data adds the question text: `q2; How satisfied are you?`. The column name stays `q2`.
- In CSV files, a line break inside a cell becomes a space, because SPSS cannot read records that span lines. The Excel file keeps the line breaks.
- Code cells are written as text in Excel, so codes such as `01` and `98` keep their form.

## Datamap

The datamap explains the export. It is in long format, with one row per column and per answer code, and one row for a column that has no codes. The headers are always in English, in this order:

| Header | Content |
| --- | --- |
| Column | The column name in the data, such as `q1` or `q3_2` |
| Question ID | The Question ID of the question behind the column |
| Question text | The full question text in the default language, repeated on every row |
| Type | The kind of question and its detail, such as `csat . 5-point`, `numeric . integer` or `embedded data . true/false` |
| Code | The answer code, as text |
| Value label | What the code stands for. Scales get one row per point, and a picture option uses its alt text |
| Notes | What blank means for the column, and other remarks, such as a column that holds unmapped values |

Embedded Data and response information columns are listed with their types. A legacy Embedded Data field that is named like an export column gets an `ed_` prefix and a note.

## Unmapped values

Answers are stored as the text the respondent saw, so Formbricks finds the code of an answer by matching that text with the options of your survey, first in the language of the response and then in any language.

An answer that matches no option is an **unmapped value**. It is never guessed and never counted as Other. In the data, its code cell holds `UNMAPPED:` followed by the text as given. The `Unmapped values` sheet, or `unmapped-values.csv`, lists each one:

| Column | Content |
| --- | --- |
| Column | The column that would have held the value |
| Question text | The question |
| Unmapped value | The text as given |
| Responses | How many responses gave it |
| Languages | The languages of those responses |
| Closest option, Closest code, Similarity | The most similar option and how similar it is |
| Likely cause | "wording differs slightly from" the closest option when the similarity is 90% or more, otherwise "no similar option" |
| Response IDs | The responses that gave it, up to a limit |
| Question ID | The Question ID of the question |

Typical causes are an option that was renamed or deleted before the survey was published and locked, or an answer sent through the API. If a question has an **Other** option, text that matches no other option reads as an Other answer and is not listed. A multi-select answer that matches no option has no cell, so it appears only in the unmapped values list.

## SPSS syntax file

With **Add SPSS syntax file** the zip contains `labels.sps`, UTF-8 with a byte-order mark. It reads the codes file into SPSS and sets up the labels, so that you do not have to.

Before you run it:

- Open the file in SPSS and **set the folder in the `CD` line** to the place where you unzipped the export. Run all.
- Use SPSS in Unicode mode so that non-Latin text is read correctly. The file asks for UTF-8 when it reads the data.

What it does:

- Reads the data with an explicit variable list, so SPSS never guesses a type from the first rows. A column is numeric only when every answer code is a plain integer. If an answer code is a letter, the column is a text variable, which SPSS can label but not compute with.
- Sets variable labels (at most 256 bytes) and value labels (at most 120 bytes), cut on a character boundary. Quotes are doubled and line breaks become spaces.
- Defines a multiple response set for each multi-select with at least two option columns.
- Does not define user-missing values. Blank is system-missing.
- Reads a column that holds `UNMAPPED:` cells as text, keeps the original in a `<column>_raw` variable, then converts the column with `ALTER TYPE`. SPSS reports a warning for every `UNMAPPED:` cell it cannot turn into a number, and the file raises the warning limit so the run does not stop early.
- Reads the timestamp as UTC text and adds a date-time variable.

## Low quality responses

Mark a response as **Low quality** when it should not count, for example a speeder, a duplicate or a test. Nothing is deleted, and you can restore the response at any time.

- On a response card, use **Mark as low quality** in the header, and **Restore as complete** to undo it.
- In the Responses table, tick several rows and use the bulk action in the selection bar.
- The response type filter has **Low quality responses**, so you can review them.
- Read-only seats see the outcome of each response but cannot change it.
- Through the API, set `outcome` to `lowQuality`, or to `null` to restore, with `PATCH /api/v3/responses/{responseId}`. `POST /api/v3/responses/batch-outcome` does it for up to 100 responses at once.

What changes for a Low quality response:

- It is left out of the Analysis export by default, and the count line says how many were left out. If your filter selects Low quality responses, the export contains them.
- The Responses table shows its outcome, and the export has an `outcome` column that reads `lowQuality`.
- Its Feedback Records are removed, so it drops out of [Dashboards](/unify-feedback/dashboards-charts). Restoring the response creates them again.

What does not change: the Summary, response counts, API lists, webhooks and integrations keep counting Low quality responses. Webhooks and API responses carry `outcome`, so you can filter on it yourself. The Standard export includes Low quality responses too.

<Note>
  Whoever marks responses needs edit rights on the survey.
</Note>
