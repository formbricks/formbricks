The **Flow** tab sits next to **Questions** in the survey editor. It shows the path respondents take through your survey on one outline, so you can check every jump and calculation at a glance instead of opening each block.

The Flow tab is there in every survey, including surveys created in CX mode.

## Reading the outline

Read the outline from top to bottom. That is the order a respondent moves through the survey.

* **Blocks.** Each block is one page of the survey. Its row shows its number, its name, its questions and how many rules it has.
* **Show if.** A block or a question shown only to some respondents carries a **Show block if …** or **Show question if …** badge that reads its condition. See [Show If](/surveys/general-features/show-if).
* **Options.** A question whose options are shown only to some respondents carries a **Show options if … (N options)** badge, and one with Hidden options a **N hidden options** badge. Click either, or **Show options if…** on a question with options, to edit them. See [Show if on options](/surveys/general-features/show-if#show-if-on-options).
* **Rules.** The rows indented under a block run after the respondent submits that block. Each row reads as a sentence, for example *If “services” includes one of Apple TV+ → Require an answer to “apple_reason”*.
  * Each kind of rule has its own colour and icon, the same on its row, in **Add logic** and in the rule's action list: **blue** for Jump to block, **green** for Set value, which changes a calculated [Embedded Data](/surveys/general-features/variables) field, **violet** for Require answer and **orange** for Mark response as Low quality, for example *If “hours” > 112 → Mark response as Low quality*.
  * A rule with several kinds of action takes the colour of its first action.
  * A rule with several actions sets them apart with a dot, and a jump comes last, after **then**: *score + 10 · Require an answer to “q3” then Block 4*.
* **Everyone else.** Under a block's rules, **All other answers will continue to** says where respondents go when none of the rules jumped. It is the next block unless you choose another block or an ending.
* **Endings.** The endings are listed last, in red. A redirect ending shows the address it sends respondents to.

The Flow tab opens with every block folded down to its row. Click a block's row to open or fold just that block, or use **Expand** to open them all; once all are open, the same button reads **Collapse**. Switching to another tab and back keeps the blocks you opened. The header also counts your blocks and endings, and its (i) explains how to read the outline.

## Editing logic

Click any rule row to open its settings right there on the outline. The rule editor is the same one described in [Conditional Logic](/surveys/general-features/conditional-logic): choose what to test, an operator and a value, then one or more actions.

The buttons at the right of a rule's row, as on a question card, let you:

* **Move up** and **Move down**, because rules are checked from top to bottom and the first jump that matches wins.
* **Duplicate** it, with the copy placed right below it.
* **Delete** it. Deleting a block's last rule also resets where everyone else goes, back to the next block.

To add a rule, use **Add logic** under a block:

* **Jump to block** starts a rule that sends respondents to a later block or an ending.
* **Set value** starts a step that sets a calculated field from an expression. It always runs until you give it a condition with **Add a condition**. See [Set Value and Expressions](/surveys/general-features/set-value).
* **Mark response as Low quality** starts a rule that marks the response Low quality when it matches. The respondent sees nothing. See [Mark as low quality](/surveys/general-features/conditional-logic#mark-as-low-quality).
* **Show block if…** shows the block only to the respondents a condition matches. An open block also shows **Show block if…** in its header, and **Show question if…** next to each question, to show a single question only to some respondents. See [Show If](/surveys/general-features/show-if).

You can switch any action of a rule between Jump to block, Set value, Require answer and Mark response as Low quality, and add more actions to the same rule. A rule jumps at most once and marks a response at most once.

Changes on the Flow tab are part of your survey draft, like changes on the Questions tab. They are kept when you save or publish the survey.

An ending's text and button are edited on the **Questions** tab.

## Rules before the first question

The outline starts with **Before the first question**. Rules here run as soon as the survey loads, before the welcome card, so you can screen respondents or route them before they answer anything. They also run when a respondent opens the survey through a [start-at link](/surveys/link-surveys/start-at-block), so a screener can't be skipped that way.

Nobody has answered anything yet, so these rules read only:

* [URL parameters and hidden fields](/surveys/general-features/hidden-fields), for example a `panel_id` your panel provider adds to the link
* calculated [Embedded Data](/surveys/general-features/variables) fields
* response details the browser knows, such as the page URL or the survey language

And they can only:

* **Screen out**: jump to an ending. The respondent sees only that ending, not the welcome card or any question.
* **Jump to a block**: start the respondent on a later block. With a welcome card, the welcome card still shows first and leads to that block. A jump also takes priority over a start-at link.
* **Set value**: change a calculated field. Its value is saved with the response when the respondent submits the first page.

Rules are checked from top to bottom: the first jump that matches wins, and every matching Set value step runs. When no rule jumps, the survey starts as it always does. Use **Add logic before first question** to add a **Jump to block** rule or a **Set value** step.

### What a screen-out records

A screen-out leaves a finished response straight away, even though no question was answered. It holds the ending the respondent was sent to, the URL parameters and hidden fields that caused it, and any values the rules set, so you can check your screener in the responses.

<Note>
  For now, a screened-out response counts as **Completed**: it appears in your completed responses and counts toward **Close survey after N responses**. Keep this in mind when you set a response limit on a survey with a screener.
</Note>

When spam protection is on, the survey runs its reCAPTCHA check before it records a screen-out, as it does before the first answer.

### Trying a screener in the preview

The editor preview has a **Test values** button next to **Restart**. Enter values for the survey's URL parameters and hidden fields, then click **Restart with these values**: the preview starts over as if the link had carried them, so you see exactly where a respondent with those values goes. **Clear** removes them. The values only affect the preview.

You can also open the survey's link with the parameters added, for example `?panel_id=12345`, as before.

## When something is wrong

If a rule is incomplete or points at something that no longer exists, saving or publishing the survey opens the Flow tab, opens the block and the rule the error message names, scrolls to it and outlines it in red. A folded block with a flagged rule is outlined in red too. The red outline goes away as soon as the rule is fixed.

## Logic written through the API

Surveys built through the [Management API](/api-v3-reference/introduction) or [MCP](/platform/mcp/overview) can carry logic too. Everything a survey holds shows up on the outline, so you can check what an AI or an integration wrote before you publish.

A row marked **Read-only** holds something the Flow tab can show but cannot edit yet. Its other rules stay editable.

## Where logic used to be

Logic used to sit at the foot of each block on the Questions tab, under **Conditional Logic**. It has moved to the Flow tab, and your existing rules appear there with nothing for you to do.

The first time you open the editor after the change, the Questions tab shows a **Logic has moved to the Flow tab** notice with an **Open Flow** button. Once you have opened the Flow tab, the notice no longer shows in that browser.
